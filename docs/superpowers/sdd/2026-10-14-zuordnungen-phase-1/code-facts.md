### How `approves`, `of`, `subject`, `replaces` are represented
- `subject: int | None` on `Statement` (top-level payload key on obligation/decision). `None` = first version, thread is named after the row id of that first version (`fold :583`). Non-None = id of the thread's first version.
- `approves: int | None` (payload key on obligation/decision): the id of the **proposal version** being made one's own. Requires `subject` non-null and `responsibility == "direct"`.
- `of: int | None` — only on rejections: id of the rejected proposal version. Payload key `"of"`.
- `replaces: int | None` — decision body only: id of another decision **thread** (checked `view.kinds.get(replaces) == "decision"`).
- All four are event ids (ints, 1..2^53-1).

### How `fold` builds threads (`:552-606`)
Iterates rows in chain order. `payload is None` -> id into `erased`, skip. `parse_statement` None -> skip. Rejection: finds `thread_of.get(of)`; if found adds to that draft's `rejected`; else ignored. Version: `subject = row_id if statement.subject is None else statement.subject`; a non-None subject that is neither in `drafts` nor in `erased` is skipped; `draft.kind != statement.kind` skipped; `approves` checked by `_approvable` (not already approved/rejected; either erased or an OPEN version of this draft) and added to `draft.approved`; then `Version` appended, `thread_of[row_id] = subject`. Result `dict[subject, Thread]`; `_Draft` (`:527`) is a private mutable dataclass.
- `winner()` (`:504`): latest DIRECT version; else latest OPEN version that is neither rejected nor approved; else `None`.
- `pending()` (`:513`): open, unrejected, unapproved versions **newer than the direct winner**; with no direct winner all candidates except the last. The winner is never in the list.
- `Thread.versions` holds every standing version in chain order (approved/rejected proposals included).

### The assertion payload's top-level discriminator
`payload["assertion"]` holds the kind (`"obligation"|"decision"|"rejection"`); the **event** kind is `"assertion"` (`ASSERTION`, `core/assertions.py:87`). Actions use `payload["action"]` under event kind `"action"`; observations use `evidence` + `channel_identities` etc. under event kind `"observation"`. Everything reading assertions goes through `log.read_by_kind(conn, ASSERTION)` — a new assertion kind with event kind `"assertion"` is picked up automatically by `read_threads`, `redact._assertions`, `verify` dispatch (`row.kind == ASSERTION`), but **every consumer then has to tolerate the new payload**: `fold` silently skips rows `parse_statement` returns None for (so unknown kinds vanish from lists), `assertion_problem` returns the unknown-kind message for them (so `verify` reports `assertion has no valid form: the assertion kind is none of obligation, decision, rejection` for any new kind written before the model learns it), `redact` finds them by `sources_named` (source-agnostic, fine), `_rows()` feeds the whole log to every `fold`.
