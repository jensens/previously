## After the PR opened (#26, a4c04f2): the maintainer's review of the reader fallback

The maintainer, 2026-10-15, on "readers fall back to the fold on any error": two paths that compute the graph are wrong; the fold must be replaced, not kept as a fallback; on a conflict the first wins and the second retries, bounded (1-2 times); taking another code path is wrong. Asked to argue or refute; argued in the conversation, the maintainer approved the fix round ("ja, freigabe fuer die fixrunde").
Ruling F-c: readers never fall back to the whole fold and never rebuild. Only `previously project` rebuilds a projection (first build, version change, forced repair), like a migration in the upgrade step. A reader (CLI and MCP) and `redact` catch up incrementally only; meeting no state row or another version, they fail with a sentence that names `previously project`. A same-version rebuild between a reader's catch-up and its snapshot is retried once (catch up again, new snapshot, check again); a second miss is an error. `ProjectionGap` and `StorageError` are errors, not fallbacks: the log has no gaps by construction, so a gap is damage the fold would answer over silently; a missing table or missing privilege is misconfiguration the fallback hid. The MCP server checks the graph projection before it serves and its readiness probe says not ready while the projection isn't at this code's version. — why: by code reading, a reader of version n meeting version n+1 truncates and rebuilds inside a call (35 s at 100k), and the other version does the same back: retrying can't converge and the fallback disguised the ping-pong as "slower"; at 100k the fallback costs 17 s per call, an outage that looks like slowness. Same-version catch-ups already take turns under the state row lock, so "first wins, second waits" holds without a retry. — cost if wrong: graph reads fail instead of being slow while the projection isn't usable; old pods fail graph calls during a rolling update that changes the projection version until replaced; the upgrade must run `previously project` before serving (a8: migration 0006 means a first build).
Kept, and why it is no fallback: the whole fold stays for `verify` and `project --check` (an independent recomputation; reading the projection would check itself), for `--as-of` (the projection holds the present only) and, for now, on the write path (map point, its own step). The per-thread fold is the projection's own building block — one semantics.
